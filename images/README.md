# 이미지 추가 안내

현재 저장소에는 실제 우수상 증빙 이미지가 추가되어 있습니다. 서비스 화면은 가짜 이미지나 임시 캡처를 만들지 않고, 개인정보와 팀원 동의를 확인한 실제 자료만 추가합니다.

README에는 존재하는 `award.jpg`만 직접 표시하며, 아직 없는 서비스 화면은 파일명만 안내하므로 깨진 이미지가 보이지 않습니다.

## 수상 증빙 파일

카카오톡으로 전달된 원본 사진은 재압축하거나 내용을 수정하지 않고, 저장소 규칙에 맞게 파일명만 변경해 복사했습니다.

```text
images/award.jpg
```

README의 `수상 및 증빙` 항목에는 다음과 같이 연결되어 있습니다.

```markdown
![SW 잡브릿지-DAY 통합프로젝트 발표회 우수상 증빙](images/award.jpg)
```

사진에는 4인 팀원의 이름과 상장 번호·협회장 직인이 보이며, 전화번호·이메일·생년월일·주소는 보이지 않습니다. 다른 용도로 재사용할 때는 이름 공개 범위를 다시 확인합니다.

## 개인정보 제거 체크리스트

- 이름 공개 범위에 팀원 전원이 동의했는가
- 전화번호, 이메일과 생년월일을 가렸는가
- 주소, 주민등록번호와 서명을 가렸는가
- 브라우저 탭, 북마크, 계정 프로필 사진이 노출되지 않는가
- AWS 계정 번호, 리소스 ARN, 버킷명과 RDS 주소가 보이지 않는가
- API 키, GitHub Secrets, 환경변수 값이 보이지 않는가
- 실제 사용자 닉네임과 감정 기록을 익명화했는가
- 관리자 화면의 신고 내용과 대상 사용자를 익명화했는가

## 캡처 원칙

- 데모 계정을 사용하고 실제 사용자 데이터를 캡처하지 않습니다.
- 한 화면에 보여줄 기능을 하나로 제한합니다.
- 브라우저 개발자 도구, 주소 표시줄과 운영 도메인은 필요할 때만 포함합니다.
- 모바일 캡처와 데스크톱 캡처를 섞기보다 같은 비율로 통일합니다.
- 긴 페이지는 핵심 영역을 잘라 사용하되 기능의 맥락이 사라지지 않게 합니다.
- 이미지에 설명을 직접 많이 넣기보다 README 캡션으로 설명합니다.

## README 반영 예시

이미지 파일을 추가한 뒤에만 다음과 같이 연결합니다.

```markdown
### 개인 방

![감정과 오브젝트를 배치한 개인 방](images/private-room.png)

### 광장 완성 결과

![여러 참여 기록으로 생성한 광장 최종 이미지](images/plaza-result.png)
```

서비스 화면이 없거나 개인정보 확인이 끝나지 않았다면 README에는 다음 안내만 유지합니다.

> 서비스 화면은 개인정보 확인 후 추가 예정입니다.
